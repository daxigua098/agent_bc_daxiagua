# 交付物与文档规范

## 文档种类

产品需求文档（PRD）、玩法规则说明书、结算规则表、运营活动方案、UI 文案、测试用例、验收与对账清单、上线检查表。每份文档开头写明：适用范围、目标市场、依据来源、版本与日期、变更记录。

## 玩法规则说明书骨架

1. 玩法名称与别名（中英）
2. 适用市场与发行版本
3. 玩法流程：下注 → 封盘 → 开奖/赛果 → 结算 → 派彩
4. 盘口与赔率定义，含赔率来源与版本
5. 结算规则：判定依据、示例（正常、走盘、半赢/半输）
6. 限额与封盘规则
7. 异常处理：中断、改期、改判、超时
8. 责任边界：自研还是厂商、以谁的结果为准

没有数值示例的结算文档不算完成。每个规则至少 3 个例子，写清本金、赔率、结果、净额。

## PRD 骨架

背景与目标 → 用户角色与场景 → 功能清单 → 关键流程与时序 → 数据与字段 → 状态机 → 边界与异常 → 报表与指标口径 → 依赖与风险 → 验收标准。

## UI 文案规范

需要覆盖这些场景，且措辞与后台规则一致：下注确认（含赔率变动提示）、余额不足、超出限额、注单已接受/已结算/已取消、提现进度与审核状态、活动规则与流水要求、负责任博彩提示。涉及金额的地方写明币种与到账时间口径。

## 测试用例清单

至少覆盖：

- 结算边界：走盘、半赢半输、比分刚好等于让球数
- 异常单：中断、改期、改判、串关部分延期
- 并发与幂等：重复提交、重复回调、同时下注与提现
- 限额与余额：超限、余额不足、跨档限额
- 时间与精度：跨天、跨时区、分位差
- 对账：制造一笔差异，验证是否被发现并归类

## 验收与自检清单

交付前逐条确认：

- 所有数字有来源标注（厂商文档 / 运营确认 / 待核实）
- 金额、赔率、时间的口径已写明
- 注单状态机唯一且与代码一致
- 异常单处理规则已给出并可执行
- 对账方式已定义，差异分类已固定
- 没有把玩家数据、密钥、真实账号写进文档或代码
- 本次项目的结论已追加到 learnings
