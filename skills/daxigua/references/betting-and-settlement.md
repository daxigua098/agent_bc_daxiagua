# 赔率、注单与结算

## 赔率表示与换算

用 D 表示十进制赔率（欧赔）。

- 欧赔（Decimal）：D，本金 1 赢回 D。
- 港赔（HK）= D − 1。
- 美式（US）：D ≥ 2 时为 +(D − 1) × 100；D < 2 时为 −100 / (D − 1)。
- 马来赔 / 印尼赔也常用，但各厂商口径与显示习惯不一致 —— **接入前必须用厂商规则文档核对**，不要凭记忆实现。

常用公式：

- 单注返还 = 本金 × D
- 隐含概率 = 1 / D
- 一组盘口的理论抽水 = Σ(1 / Dᵢ) − 1
- 串关赔率 = 各腿赔率相乘（∏ Dᵢ），任一条输则整单输
- 走盘（push）：本金原额退回
- 半赢：返还 = 本金 + 本金 × (D − 1) / 2
- 半输：返还 = 本金 / 2
- 返奖率 RTP = 1 / D（标注口径：理论还是实测）

浮点陷阱：金额与赔率一律用整数最小单位或高精度十进制，禁止用二进制浮点累加后四舍五入，否则对账必然出现分位差。

## 注单状态机

最小可用状态集，别在项目里临时发明状态名：

`pending（待确认）→ accepted（已接受）→ settled（已结算）`，旁支为 `cancelled（取消）`、`void（作废退款）`、`re-settle（重算）`。

要点：

- 每次状态变更写审计记录（谁改的、什么时候、依据什么）。
- 重算只允许产生新版本，不得原地覆盖金额。
- 状态与金额要能互相校验：已结算注单的净额之和必须等于派彩流水。

## 必须写清的字段

注单表至少包含：注单号、会员 ID、玩法大类、具体玩法与盘口 ID、下注时的赔率、赔率版本、本金、币种、下注时间（含时区）、赛事/局号、结算依据（厂商报单号）、状态、净额、结算时间、是否参与流水、是否参与返水。

「赔率版本」与「是否参与流水/返水」是最常被漏掉、事后最难补的两个字段。

## 异常单清单

每上一个玩法，把下面这些逐条给出处理规则，并配数值示例：

1. 比赛中断、取消、改期、提前结束
2. 赛果改判或数据源更正
3. 赔率变动：以接受时赔率还是结算时赔率为准
4. 部分结算（串关中某腿延期，其余腿先结算与否）
5. 重复提交与并发扣款（幂等键设计）
6. 封盘瞬间的注单裁决依据
7. 超限与限红冲突、余额不足与部分成交
8. 厂商长时间未返回结果时的超时策略（挂起、自动作废、人工介入）

## 对账

- 以厂商结算报单为准，本地重算结果作为差异项列出，人工裁决后再落库。
- 差异分类先固定下来再统计：时区、状态机不同步、精度与舍入、重复回调、手续费、汇率、人工补单。
- 每日自动对账 + 差异清单归档；差异未处理完之前不要调整历史数据。
