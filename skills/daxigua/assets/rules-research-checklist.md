# 平台玩法调研：采集清单

用途：把目标平台的彩种、玩法、赔率、中奖算法采全，再出《玩法规则说明书》。

原则：**目标是能独立复核，不是截图数量多。** 每个数字都要能看出它出自哪个页面。

---

## 0. 先记三项（文档首部必填）

这三项不要替用户猜，写进文档第一页：

| 字段 | 说明 |
| --- | --- |
| 目标市场 | 这个产品最终面向哪个国家 / 地区 |
| 运营主体 | 公司或团队名称 |
| 持牌情况 | 牌照机构与编号；没有就写「未持牌」 |

---

## 1. 每个彩种要采的七项

| # | 内容 | 采到什么算齐 |
| --- | --- | --- |
| 1 | 玩法项名称 | 完整名称 + 平台叫法（如「任四组选 6」），有别名一并记 |
| 2 | 注数与单注金额 | 全包注数；单注最小单位（如 1 厘 = 0.001 元） |
| 3 | 赔率 / 抽水 | 界面显示的赔率或抽水百分比，分档就分档记 |
| 4 | 中奖判定 | 判定规则原文 + 至少一个平台自己的中奖示例 |
| 5 | 派奖公式 | 派奖金额与算法（是否除以注数、是否另扣手续费） |
| 6 | 限额与封盘 | 单注上限、单期上限、封盘时间或倒计时 |
| 7 | 异常处理 | 中断、改期、改判、超时未结算时平台的说法 |

---

## 2. 这些内容一般在哪几个页面

- 玩法说明 / 规则页（通常从彩种入口或「玩法」按钮进入）
- 投注页的赔率表与限额提示（限红数字常在输入框附近）
- 活动或公告里的规则补充（抽水调整、限时玩法常见于此）
- 历史开奖与派奖记录（用于核对派奖公式）

---

## 3. 文件怎么存

- 目录：`docs/daxigua/raw/<彩种名>/`
- 命名：`<彩种>-<玩法>-<内容>.png`，例：`任四-组选6-赔率表.png`
- 格式优先级：**带文字的 PDF > 完整 HTML > 截图**

---

## 4. 三个坑

1. Angular / React 单页应用「网页另存为」如果只存 HTML 会得到一个空壳，要选「完整」，或者直接用浏览器「打印 → 另存为 PDF」。
2. 赔率是动态的。截图必须带上页面上的时间或期号，否则事后无法判断是哪个版本。
3. 不要采集账号、余额、银行卡、支付记录这类信息。截图前把账号与余额区域裁掉。

---

## 5. 不需要采的

- 登录流程、会话、验证码（与规则调研无关）
- 投注记录与资金流水
- 任何第三方账号信息

---

## 6. 采集顺序建议

先拿一个彩种里的一个玩法，把七项采全，先出一页样张。确认字段口径对了，再批量采剩下的，避免采完二十个页面才发现缺字段。
